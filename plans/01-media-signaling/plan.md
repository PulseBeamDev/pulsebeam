# Native media signaling and client cutover plan

## Authority and strategy

Implement `spec.md` as one end-to-end `pulsebeam.media.v1` outcome. The supplied combined spec and checked-in v1 schema supply the intended semantics; HEAD and executable tests determine what is already working. Historical status labels alone are not proof of approval or acceptance. HEAD `9730fbd9` has native server v1 admission, codec, participant signaling and acceptance tests, but Agent core still imports legacy `pulsebeam_proto::signaling`, encodes `ClientIntent`, and applies `ServerState`. Web/React/Meet still expose slot/publication-ID and app-owned attachment plumbing. Therefore validate and repair the server boundary rather than rebuild it, migrate the portable policy and both hosts, then remove the old contract only after all consumers move. The historical server-only plan is implementation history, not this project's acceptance record.

Keep `agents/pulsebeam-agent-core` the sole owner of portable desire, canonical Catalog/Mapping, revision, retry, renewal, sender reservations and topic policy. Native and Web execute effects and return generation-tagged events. React owns hook/component lifetimes, physical capture and rendered demand; the Agent borrows capture and owns remote logical handles; the server retains authoritative assignment. Reuse the existing core effect/event loop, host transports, Web facade/media registry and server participant scheduler, deleting superseded state rather than introducing a second media authority. Preserve `crates/pulsebeam-rtc` as a separate transport crate, not a new Agent dependency.

## Outcomes and dependencies

1. **Prove and complete the existing server boundary.** Audit `crates/pulsebeam-proto/{proto/signaling_v1.proto,src/codec.rs}` and `crates/pulsebeam/src/{control,participant,track.rs}` against the spec, starting from `participant/v1_server_acceptance_tests.rs`. Extend only missing proofs or fixes for enabled zero-based SDP sections and 32-per-kind/direction caps; canonical identity, room-unique external IDs, immutable WHIP labels and previsibility snapshot sizing; fresh/stale/zero Intent atomicity; complete audio/video preview and occupant generation; layer floors; Catalog-before-Mapping addition, Mapping-before-Catalog removal; exact encoded retry, replacement-channel snapshot and terminal priority; matching authorization lease/expiry and generation-safe one-time teardown. Inspect bounded renewal-response overflow caller handling before changing it. Keep shard-owned nonblocking packet/control handoffs and separate WHIP/WHEP HTTP/SDP behavior. **Done:** real participant-loop, negotiator, controller and codec tests demonstrate each invariant, including malformed/bomb and backpressured/late-completion paths; `cargo test -p pulsebeam-proto` and the server owner fast gate pass. This boundary can be proved independently of the Agent migration; do not call historical green claims current evidence.

2. **Replace legacy portable Agent policy with v1.** In `agents/pulsebeam-agent-core/src/{model,signaling,agent,effect,event,topic}.rs` and its tests, consume generated `signaling_v1` types through the bounded shared codec; remove `ClientIntent`/`ServerState` patch state and MID-as-identity mapping. Model immutable `(kind,label)` sender reservations and connection-local SDP media-section indices separately; default topology to 2/2 senders and 8/16 receivers, with independent 32 caps. Maintain complete application desire separately from accepted Intent revision, atomic Catalog (snapshot revision 1, ordered deltas, replacement snapshots), and complete server Mapping for both kinds. Resolve selectors through Catalog, validate identity/kind/revisions/causality, retain unmapped desire without invented assignments or implicit reconnect, and make catalog removal invalidate handles/policy while Mapping omission does not. Emit a new Intent only when application desire/valid catalog selection changes or a new connection needs reconstruction; accepted revisions track the connection. Explicit Reconnect resets only connection-local state and fences retired-generation events. Retry indefinitely with jittered exponential delay capped at 10 seconds while desired-connected, reset only on reconciliation, and use the latest supplied credential for matching renewal and recreation. Preserve existing reliable/unreliable topic transport and latest/ordered policy while exposing lazy, cancellable async subscription and asynchronous publish. **Done:** deterministic core tests cover fresh/stale Catalog, both Mapping kinds, label/capacity invariants, numeric-option boundaries, retry/reconnect/renewal, generation fences and topic cancellation. Depends on the stable checked-in v1 schema, not on final schema renaming; server verification may proceed in parallel.

3. **Execute the common policy in native and browser hosts.** Adapt `agents/pulsebeam-agent-native/src/{runtime,ffi}.rs` and `agents/pulsebeam-agent-web/src/{engine,browser,ffi}.rs`, plus `agents/pulsebeam-agent-web/web/{agent,types,media-registry,remote-media}.ts`, to construct fixed-topology SDP, derive actual zero-based negotiated RTP indices, open the reliable ordered signaling channel, transmit/receive independent raw-LZ4 envelopes, execute core effects, and bind only authoritative Mapping to RTP receivers. Carry generation tokens across asynchronous HTTP, RTC, media and token completions; close old resources on explicit reconnect/disconnect. Present synchronous, atomic, machine-readable sender-capacity and finite-uint32 option errors, including before browser WASM initialization: the Web facade may queue validated immutable reservations until core starts but must not become a second reconciliation policy. Borrow physical tracks and never stop them; expose opaque stable local handles, fresh remote handles after catalog reappearance, and topic async iteration without eager registration. Preserve optional low-level browser attachment escape hatches. Regenerate UniFFI/Web assets through owning recipes, not edits to generated files. **Done:** native, Web strict-consumer/UniFFI and browser tests verify v1 wire, negotiated indices/defaults, complete Mapping, source replacement and no capture ownership transfer, renewal/recreation, stale completion fencing and topic final-consumer cancellation. Depends on 2; server/Agent interop uses 1's verified boundary.

4. **Build React Agent and capture lifetimes.** Replace provider-required `useAgent()` in `agents/react/src/index.ts` with an offline, hook-owned Agent configured for its lifetime, explicit connect/disconnect, and a way for components to use independently owned Agents without an ambient playback provider. Implement `useMediaDevices` normalized reactive inventory, label refresh on permission and hotplug; `useUserMedia`/`useDisplayMedia` typed audio/video source handles with explicit gesture-compatible `request()` and `stop()`, normalized errors, and no option-driven display prompting. Keep old capture alive until replacement succeeds, reject and record failed replacement without stopping it, and stop stale results after stop/unmount. Track ownership per hook so multiple Agents may borrow the same capture but cannot stop one another; unmount closes only resources that hook owns. **Done:** React browser and strict-consumer tests cover initial offline state, explicit lifecycle, device inventory, gesture request, failed/stale replacement and multi-Agent source sharing. Depends on 3's public handles/facade.

5. **Replace app-owned playback and receiver plumbing.** In React components/hooks and the Web facade, expose remote video/audio as opaque Agent-owned handles with external participant ID, kind and label; local preview uses the same video-handle component. Mounting Video creates physical-pixel-height demand (zero when hidden/offscreen), aggregated by maximum over consumers; receive options replace each caller's whole policy but create no demand on their own. Allocate wire video desire to unused receivers first, then reclaim hidden demand, never more than negotiated capacity; warn and leave surplus visible requests unmapped without evicting useful visible tracks or letting hidden minima pin capacity. Actual attachment follows server Mapping; removal makes retained handles inert. Agent-owned aggregate Audio plays only while mounted. Scope `onPlaybackError({error,retry})` to each Audio/Video instance so retry can run from a user gesture. **Done:** browser tests show 17 visible videos on 16 receivers, hidden reuse and multi-consumer aggregation, unchanged desire on missing Mapping, inert removed handles, isolated Audio and gesture retry. Depends on 3; local preview integration uses 4's capture handles.

6. **Migrate applications and integration consumers.** Move `apps/meet/components/*`, `apps/meet/hooks/*`, `crates/pulsebeam-cli/src/main.rs`, `crates/pulsebeam-simulator/src/tests/*`, README/examples and contract fixtures to the high-level v1 handles/topics/capture model. Remove Meet's parallel publication/mapping and raw attachment management, preserve screen restart and multi-Agent lifetime behavior. Keep CLI/simulator encoded-frame transport contracts where they remain valid, changing their Agent signaling/identity usage rather than replacing the media pipeline. Check docs/examples by tracked references, not an assumed top-level `examples/` directory. **Done:** Meet browser flows cover screen restart, multiple Agents and catalog/reconnect/renewal; CLI and simulator exact native interop tests and affected consumer gates pass, with no normal application-owned receiver indices/Intent. Depends on 4 and 5.

7. **Perform single-schema cutover and remove dead code.** After all producers/consumers use v1, move the v1 schema contents to `crates/pulsebeam-proto/proto/signaling.proto` under `pulsebeam.media.v1`, remove `signaling_v1.proto` and the old schema, update `build.rs`/`src/lib.rs` and imports, and regenerate all bindings through their owners. Preserve v1 wire field numbers and codec framing; reconcile stale schema prose with the approved server contract rather than adding a new wire rule. Delete active legacy decode, patch/delta retry, obsolete helpers and migration APIs, with no version fallback. Verify WHIP/WHEP stay separate. **Done:** repository reference checks find one media schema and no active legacy consumers; proto, generated-client, affected owner tests and checks pass. Depends on 1, 3 and 6.

8. **Accept end to end.** Run exact affected tests and the nearest owner fast gates during each outcome; run impacted RTC/Web/React/Meet browser boundaries when their shared behavior changes. Once implementation is stable, run root `just check` and root `just test` once for final non-privileged acceptance and record actual outputs. If a repair invalidates final evidence, rerun affected slow owners and reuse unaffected passing evidence. **Done:** no unresolved gate failures, including native server and browser/server integration; record any unavailable privileged eBPF or advisory seed sweep as outside the ordinary gate. Depends on 7.

## Constraints and principal risks

No native renegotiation/ICE restart, mixed-version fallback, new topic transport, server-invented receiver mapping, packet-rate shared locks, broad congestion/routing redesign, device-output routing, gain, recording or priority eviction of useful visible video. Treat zero-based SDP indices as connection coordinates, not identity. Admission cannot expose a Catalog that cannot be snapshotted within 32,768 protobuf bytes; pending encoded output and terminal messages cannot be overtaken under backpressure. Reconcile option values without silently quantizing client desire; validate public numeric inputs synchronously. Browser initialization, capture replacement and retired RTC/renewal callbacks require explicit generation/ownership fencing. Default capacities and authority follow `signaling_v1.proto` and the combined spec where old README/tests disagree. Keep the server boundary independently reviewable, but do not declare repository cutover complete until dependent consumers and final schema removal pass.
