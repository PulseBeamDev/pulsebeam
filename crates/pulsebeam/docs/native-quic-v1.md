# Native QUIC v1 protocol

Contributor specification for the opt-in Linux Rust Agent and edge. This is not a public deployment guide. The application protocol does not depend on QUIC connection IDs, TLS exporters, socket addresses or QUIC stream numbers. A future authorized WebTransport session could carry the same ordered bytes and datagrams; v1 does not implement that carrier.

## Bootstrap and ownership

1. Use the existing HTTPS edge selection and `POST /api/v1/native/admissions`, with bearer authorization and JSON `{ "profile": "pulsebeam-rt-v1", "room": "stage" }`. Omit `room` for a roomless session. The absent-profile request and its `{ "owner": "…" }` reply remain unchanged. An unknown profile is rejected, not treated as WebRTC.
2. The opt-in response adds `profile`, `authority` (object with `host`, a TLS DNS name, and `port`, an integer in 1..65535) and `valid_for_ms` (positive and at most 10,000). Keep the whole JSON within 1,024 bytes. No authority field is derived from request forwarding headers. Require configured bind and advertised endpoints for each logical shard. The controller reserves the selected partition on that shard and associates the lease with the issued proof, authenticated principal, requested room and QUIC profile. At most one live placement lease per proof; a valid continuation replaces an unredeemed lease. Consume the lease when binding a new attempt, retaining the attempt's association correlation for same-association replay. Expiry/cancellation releases the pin; issuance does not create presence.
3. Connect to the advertised authority using QUIC v1, TLS 1.3 and ALPN `pulsebeam-rt-v1`. Verify the normal certificate chain and hostname on HTTPS and QUIC. Do not offer or accept 0-RTT or start work before TLS and DATAGRAM budget checks. One dedicated address per logical shard; no change to WebRTC UDP, no inter-node hop in this profile.
4. The first application message is `Admit` on the first client-opened bidirectional stream. The server revalidates current placement/lease, authenticated identity and room, the existing owner proof, nonzero attempt, and successor receipt before selecting a controller ticket. Hash the exact `Admit` body using a request-binding domain distinct from `for_native`; neither a new source address nor a different connection ID changes those bytes. A matching attempt can retrieve only its own result on the same association and cannot attach another association. If a result was lost with the association and no usable successor is known, fail safely rather than issuing a fresh owner proof as a recovery fallback.
5. The controller's existing authorization and ownership commit/retire boundary gates presence. The shard then admits `AdmitResult` to the stream before ordinary output. Recovery/move uses the existing successor authorization and bounded latest-intent reconciliation. A continuation may request a placement lease for its existing family by including `owner` and `successor_receipt` in the opt-in issuance JSON. The controller validates both and does not mint a new family. Cap that request at 2,048 bytes; keep the owner proof unchanged and encode the binary receipt as unpadded base64url. The legacy request retains its original limit. Retire the old room exposure, queued application input and all old binding lifetimes; never replay payloads into the new session. A successful same-association network move retains its binding lifetimes. Expiry, revocation, close or a superseding commit fence all old output and input immediately.

## Reliable control stream

Each frame is `length:u32be | kind:u8 | body`. Length includes the kind, not the prefix. Reject lengths outside 1..9,269 on the prefix, then check direction, phase and kind-specific length before growing the body buffer. Unknown kinds, extra streams, invalid lengths, truncation at FIN, inadmissible phase and malformed records are terminal. A valid but denied proposal remains scoped to its resource. One partial input and one pending output per association. Process frames in stream order; do not advance handoff progress until the last byte of that frame enters Noq's bounded stream send path. That progress does not acknowledge remote application processing.

| Kind | Direction and phase | Body |
| --- | --- | --- |
| `0x01` Admit | client to edge, first only | Layout below; at most 9,268 bytes |
| `0x02` AdmitResult | edge to client, first only | status `u8`; on success append connection ID (16 UUID bytes), participant (`str16`, 1..36 bytes), room (`str16`, 0..36), and `str16`-length-prefixed binary native `RtpCapabilities` (0..4,096 bytes); the server result is at most 4,191 bytes; reject unrepresentable capabilities rather than truncate |
| `0x03` ClientState | client to edge, admitted | unchanged `ClientStateBatch`, 1..4,096 bytes, up to 16 records |
| `0x04` ServerState | edge to client, admitted | unchanged `ServerStateBatch`, same bounds |
| `0x05` Renew | client to edge, admitted | request revision `u64be`, token (`str16`, 1..8,192 bytes); one in flight |
| `0x06` RenewResult | edge to client, admitted | request revision `u64be`, status `u8`, accepted lease revision `u64be`, expiry `u64be` Unix seconds; both acceptance fields zero on rejection |
| `0x07` Close | either, admitted | empty; terminal for application sends |
| `0x08` DataControl | either, admitted | existing standalone `NativeDataControl` encoding, 1..145 bytes, with the codec's DATA-control preflight and role limits |

`str16` means octet count (`u16be`) followed by exactly that many octets, with no terminator. Text is UTF-8; opaque proof is visible ASCII and token satisfies the existing compact token parser. `Admit` body is, in this exact order: `attempt:u64be` (nonzero), room (`str16`, absent if empty), owner proof (`str16`, 1..256), bearer token (`str16`, 1..8,192), successor receipt (`str16`-length-prefixed bytes, 0..768; nonempty only with a room). The proof identifies the placement lease; there is no second lease credential in this frame. Reject trailing bytes, invalid IDs or inconsistent optional fields before allocating individual values. Admission status: `0` accepted, `1` denied, `2` stale/wrong placement, `3` attempt unavailable, `4` capacity; any other value is malformed. Failed admission has only the status byte and is followed by close. Renewal status: `0` accepted, `1` rejected. The controller still derives expected CAS revision from the current authorization lease, verifies off the control loop, checks identity/grants and expiry, and installs only if that revision remains current. The request revision only correlates the Core credential operation. Grant observation remains separate. A close frame or FIN is not a remote application receipt; open/partial transport teardown retires local state within its deadline.

## Datagram bindings

Each application datagram is `kind:u8 | binding:u16be | payload`; kind `1` is one intact DATA_V1 record, `2` one RTP packet, `3` one RTCP packet or valid compound record for that binding. Binding zero, unknown kinds, mismatched formats/sources and missing or retired installs never create or change resources. Allocate binding IDs monotonically in the data-sender direction, once per association, without wrap or reuse. Feedback resolves in the reverse lookup for the associated RTP binding; it does not allocate from or alias the opposite sender namespace. Fence by association, direction and complete accepted resource/transport incarnation before parsing payloads. Confirm local installation against actual endpoint facts; a proposed binding alone conveys no authority.

Add explicit QUIC alternatives to `TrackBinding.transport`: field `4`, `QuicDataV1Parameters` (`uint32 binding_id = 1`, `uint32 version = 2`, `fixed64 incarnation = 3`, `DataV1Delivery delivery = 4`); field `5`, `QuicRtpParameters` (`uint32 binding_id = 1`, `fixed64 incarnation = 2`, `RtpCodecParameters codec = 3`, `fixed32 primary_ssrc = 4`). Both IDs and incarnations are nonzero. The RTP codec carries payload type and feedback facts; initially accept one nonzero primary SSRC, no RTP header extensions, no SDP MID and no RTX stream. Only QUIC-native sessions may send them. Leave all existing protobuf field numbers, RTC state validation, SCTP channel 0 framing, SCTP DATA_V1 bits and Fabric wire unchanged. QUIC resource validation rejects RTC-only transport arms and unsupported capability selections, while legacy RTC clients only ever receive bindings with arms they already understand.

At the path floor, 1,155 bytes of DATA_V1 plus 3 envelope bytes must fit under the negotiated datagram limit. The transport uses 8-byte CIDs and caps nonfragmenting UDP at 1,200 bytes (1,248 bytes with base IPv6/UDP headers). Use Noq's current limit, not a fixed payload guess, both at admission and send. Do not fragment at the QUIC layer, change DATA fragmentation, or truncate. If a path drops below the usable floor, fence the affected association and report continuity loss; do not retry a partial record. Reliable, Unreliable and Latest all carry canonical records. Reliable application receipts and repair stay on native control; Noq ACKs are not replacements. Use existing addressed Reliable frontiers, bounded Unreliable gaps, complete Latest units and independent subscribers.

RTP uses supported H.264 and Opus profiles. Keep timing/SSRC/sequence and feedback state within the admitted lifetime; keyframe demand uses RTCP PLI, and applicable NACK repair stays bounded. Repacketize H.264 at the QUIC endpoint when necessary; reject oversized Opus units or surface receive loss. Never tunnel SRTP or change Fabric packets. QUIC owns congestion and recovery; application staging favors control, sparse data and freshness without retaining stale encoded input across lifetimes.

## Initial bounds

These are maximums or configured defaults, not performance targets. Count staged, backend and socket storage separately. Backend congestion pacing and the shard's runnable budget must both be respected.

| Owner | Bound and outcome |
| --- | --- |
| Placement | 10 s provisional pin, bounded at 64 per shard; full returns capacity before ownership commit |
| Endpoint | 64 preadmission associations and 256 total per logical shard; retire unredeemed associations after 5 s even with traffic; Noq Initial buffering 16 KiB per incoming and 256 KiB total |
| Control | 32 KiB Noq send/receive windows; at most 32 controller input frames, 32 execution commands, 256 facts and one output; terminal failure on deadline or required lane exhaustion; 5 s partial frame deadline from first observed byte; retain the existing 30 s native output-progress deadline from original selection |
| Datagram/socket | Noq 8 KiB send/receive, at most one scheduled Noq datagram and one committed socket transmit; caller stages at most 16 payloads or 16 KiB per association (whichever first); set a 100 ms deadline for staged disposable media, and settle Reliable admission/failure explicitly |
| Per turn | At most 32 socket entries and 32 connections from a rotating ready queue, 16 transport events or sends per selected connection; rearm remaining due work |
| DATA/media | Existing 65,536-byte DATA unit and 64-fragment cap, existing Core/participant DATA retention and repair budgets; QUIC media packetization holds at most one encoded unit (256 KiB max) per active output and stages at most 32 RTP packets or 32 KiB per output in the applicable lifetime |
| Socket/kernel | Existing `pulsebeam_udp::BindOptions` receive/send buffer defaults of 4 MiB/2 MiB per descriptor before OS adjustment; actual socket occupancy is a measured qualification input, not hidden application credit |

Noq writes DATAGRAM before STREAM. Submit at most one payload to Noq and give eligible control a payload-free send turn between submissions. Give sparse interactive DATA priority over bounded media staging, with a fair bulk turn when both remain eligible. `SocketIo` owns a blocked send until submitted or fenced, including across reactor moves. On a physical client address change, replace the socket and call `Connection::handle_network_change`; Noq drives validation on path zero without multipath. A passive port rebind is handled on the same path. If the path cannot recover in the existing idle/recovery budget, reconcile a new authenticated association, not a new ownership claim.
