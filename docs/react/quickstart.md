# Your first React room

**See and hear another participant in a React app.**

Use Next.js for the application and token signing, and `@pulsebeam/react` for
media. The example assumes you know React; it focuses on the PulseBeam pieces.
No manual HTML entry point, Vite configuration, or PulseBeam source checkout is
needed.

## Before you start

- Node.js 22 or newer and npm.
- A compatible PulseBeam server **base URL** and registered project ID, API key
  ID, and signing secret. Your server operator supplies these credentials.
- A browser with a camera and microphone. Capture needs HTTPS or localhost;
  an HTTPS page cannot connect to an insecure remote HTTP server.

This tutorial assumes `@pulsebeam/server` is published on npm. The signing key
stays on the Next.js server and is never exposed to browser code.

## 1. Create an app

Use the usual Next.js scaffolder, then install the two SDKs:

```bash
npx create-next-app@latest pulsebeam-room --ts --app --use-npm
cd pulsebeam-room
npm install @pulsebeam/react@0.2.0 @pulsebeam/server@0.1.0
```

Keep the files generated by Next.js. In an existing Next.js App Router project,
just install the packages.

## 2. Set up your credentials

Add `.env.local` at the project root:

```dotenv
PULSEBEAM_ENDPOINT=http://localhost:7070
PULSEBEAM_PROJECT_ID=p_...
PULSEBEAM_KEY_ID=kid_...
PULSEBEAM_SECRET=sk_0...
```

Replace all placeholders with your own server and registered credentials. Set
`PULSEBEAM_ENDPOINT` to the URL that **the browser** can reach, without
`/api/v1/native`. Use an HTTPS endpoint when serving the app over HTTPS.

`@pulsebeam/server` signs participant tokens with these credentials. Signing does
not register a key or grant access by itself; the PulseBeam server must recognize
the corresponding public key.

## 3. Issue participant tokens on the server

Replace `app/page.tsx`:

```tsx
import { randomUUID } from "node:crypto";
import { signParticipantToken } from "@pulsebeam/server";
import Room from "./room";

export const dynamic = "force-dynamic";

export default function Page() {
  if (process.env.NODE_ENV !== "development") {
    throw new Error("Replace demo token issuance before deploying");
  }

  const token = signParticipantToken({
    projectId: process.env.PULSEBEAM_PROJECT_ID!,
    keyId: process.env.PULSEBEAM_KEY_ID!,
    secret: process.env.PULSEBEAM_SECRET!,
    room: "quickstart",
    participant: randomUUID(),
    expiration: Math.floor(Date.now() / 1000) + 3600,
  });

  return <Room token={token} endpoint={process.env.PULSEBEAM_ENDPOINT!} />;
}
```

The page executes on the **server**, where the signing secret is available.
Each page load mints a one-hour token for a different participant in the
`quickstart` room. `force-dynamic` prevents Next.js from reusing a prerendered
token across visitors. The browser receives only its token and the endpoint.

**Development only:** this example does not authenticate visitors or authorize
room access. The explicit production guard prevents accidentally deploying an
open token issuer. In your application, derive room and participant identities
from an authenticated session and authorize access *before* signing.

## 4. Connect and publish

Create `app/room.tsx`:

```tsx
"use client";

import { useEffect, useState } from "react";
import { Video, useAgent, useUserMedia } from "@pulsebeam/react";

export default function Room({
  endpoint,
  token,
}: {
  endpoint: string;
  token: string;
}) {
  const agent = useAgent({
    endpoint,
    token,
    topology: {
      localVideos: 1,
      localAudios: 1,
      remoteVideos: 2,
      remoteAudios: 2,
    },
  });
  const capture = useUserMedia({ video: true, audio: true });
  const [error, setError] = useState("");

  useEffect(() => {
    if (!agent) return;
    agent.local.video("camera").setSource(capture.videoTrack);
    agent.local.audio("microphone").setSource(capture.audioTrack);
  }, [agent, capture.videoTrack, capture.audioTrack]);

  const status = agent?.getSnapshot();

  return (
    <main>
      <p>Connection: {status?.connection ?? "preparing"}</p>
      <button
        disabled={!agent}
        onClick={() => {
          agent?.connect();
          void capture.request().catch((e) => setError(String(e)));
        }}
      >
        Join with camera and microphone
      </button>
      <button onClick={() => {
        capture.stop();
        agent?.disconnect();
      }}>Leave</button>
      <button
        disabled={!agent}
        onClick={() =>
          void agent?.remote.resumeAudio().catch((e) => setError(String(e)))
        }
      >
        Enable remote audio
      </button>
      <Video
        source={capture.videoTrack}
        mirror
        style={{ width: 320, height: 240 }}
      />
      {agent?.remote.videoTracks.map((track) => (
        <Video
          key={track.participantId + ":" + track.label}
          source={track}
          style={{ width: 320, height: 240 }}
        />
      ))}
      {(error || capture.error || status?.failure) && (
        <p role="alert">
          {error || capture.error?.message || status?.failure?.message}
        </p>
      )}
    </main>
  );
}
```

`useAgent` owns the room connection. `useUserMedia` captures the camera and
microphone only after a click. The labeled `camera` and `microphone`
publications send that capture. Visible `Video` components request remote video;
remote audio plays automatically when permitted by the browser.

## 5. Try it in two tabs

```bash
npm run dev
```

Open `http://localhost:3000` in two tabs. Each load creates a distinct
participant token for the **same room**.

1. Click **Join with camera and microphone** in each tab and allow browser access.
2. Wait for `Connection: connected` in both tabs.
3. Look for moving video from the other participant and listen for audio. Use
   headphones to avoid feedback.
4. If the browser blocks sound, click **Enable remote audio**.
5. Click **Leave** to disconnect and stop camera/microphone capture.

**Success means receiving the other participant's moving video and audible
microphone audio**, not merely seeing your local preview. Some browsers cannot
share the same camera between tabs; use two devices if needed (and HTTPS for
remote devices).
